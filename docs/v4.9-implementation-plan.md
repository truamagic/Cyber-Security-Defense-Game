## 明示的に除外する範囲

- 再読み込み時のセッション保存・復元。現在の「リロードで初期化」仕様はそのまま。誤操作防止は別途検討。
- EASY/NORMAL/HARDの初期SP、WAVE数、WAVEごとの敵構成・HP・撃退SP・突破ボーナス、設備費用・保守費。
- ルートパターン、追加侵入経路、Wi-Fi特殊イベントの発生条件・確率。
- 教育／報告の実際の効果・コストの変更。今回追加するのは事前の説明・判断材料。

## 検証方針

1. Node.js構文検証：js/*.js、tests/*.test.cjs。
2. 新規`tests/v49-ux.test.cjs`にて次WAVE予測、研修・報告説明、既払い強化、BCPの判断条件、画面構造とCSSを検証。
3. 既存9本のテストも全件実行し、ゲームルール変更がないことを確認。
4. 実ブラウザの受入試験：1440×900のSTEP5、844×390のドロワー、横→縦→横の回転とモーダル開閉、タップ対象、スクリーンリーダー。自動テストだけでは描画の良否は証明できないため別途実施。
5. 公開用サイトのデプロイ状況を確認。GitHub登録完了と公開反映完了を区別。

## リスクと判断

- スマホ横画面でボタンを大きくすると、左マップが少し小さくなる可能性がある。
- 画面回転とアニメーション終了のタイミングは端末差がある。数値座標の再計算を増やしつつ、実機確認を残す。
- 次WAVEの予測値は確定構成のみを表示し、抽選事故・教育効果を確定した未来として表現しない。
- 今回はバランスの因果検証ではなく、プレイヤーへの説明と操作性の改善を目標とする。
