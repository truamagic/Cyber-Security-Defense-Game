# HOSPITAL DEFENSE — C版 v4.0（本格リスク管理シミュレーション）

ブラウザ上で動く、架空の病院を守るサイバーセキュリティ・タワーディフェンスです。v3.3のチュートリアル、仮配置・射程表示、5ウェーブ、スライドパネルを維持し、**設備運用と人的・組織的な不確実性**を加えています。

## 起動

1. ZIPを展開して、`index.html` と `css/`・`js/` を同じ構造で保ってください。
2. `index.html` をChromeまたはEdgeで開きます。Webサーバーや外部通信は不要です。
3. 初心者は「🎓 チュートリアル」で操作を覚え、通常モードでは上部の難易度を選択してください。
4. マップ上の空き地点→ショップ→射程プレビュー→設置確定でタワーを置きます。
5. 新しい「運用管理」ボタンで設備の健全度や期限、保守費用を確認し、ウェーブ開始前・防衛中に対処してください。

## 難易度

| 項目 | EASY | NORMAL（初期設定） | HARD |
|---|---|---|---|
| 健全度の自然低下 | なし | 5〜10pt/ウェーブ | 10〜16pt/ウェーブ |
| 偶発的な運用イベントの基本確率 | 0% | 20%/ウェーブ | 39%/ウェーブ |
| 強化の即時成功率（健全度100・保守なし） | 100% | 約93% | 約76% |
| 職員教育の定着失敗率 | 0% | 10% | 28% |
| サポート残期間（設置時） | 実質無期限 | 5ウェーブ | 3ウェーブ |

確率は**全てゲームバランス上の仮設定**。実在する医療機関の事故発生率やセキュリティ製品性能を示すものではありません。

## 今回のC版でできること

- **健全度・実効レベル**：タワーレベルとは別に健全度（0〜100%）を持ち、健全度35%未満では実効レベルが1低下。8%以下で停止し、保守が必要です。健全度が低いと対応性能も下がります。
- **定期・応急保守**：SPを使い健全度を回復。停止していても復旧できます。
- **予防保守**：2ウェーブ有効。劣化を抑え、強化成功率と事故確率を改善します。
- **サポート期限**：経過ウェーブで減少。期限切れは防御効率を下げ、新たな運用リスクを増やします。SPで更新可能です。
- **アップグレードの不確実性**：NORMAL/HARDでは即時強化に失敗することがあります。失敗してもSPの再請求はなく、強化は**次のウェーブ終了時に自動完了**。SPを使った「追加検証」で即時完了も可能です。
- **職員教育の定着度**：研修レベルと実際に定着した教育レベルを別に記録。教育投資が効果に結び付かない場合があり、効果もウェーブごとに低下します。フォローアップ研修で改善できます。
- **報告体制への投資**：研修定着度の維持を助け、想定運用イベントの確率と人的リスクの影響を下げます。
- **運用イベント**：機器の不調、サポート・脆弱性の問題、研修効果の低下、複合障害が難易度別の確率で発生します。ウェーブあたりの追加運用イベントは最大1回です。
- **可視化**：マップ上での健全度バー、運用リスクの予測%、タワー別の状態、保守メニュー、イベントログを表示します。
- **終了成績**：通常の防衛結果に、運用インシデント数、強化遅延数、研修定着失敗数、保守投資額を追加しました。

### ゲームのコツ

- タワーの強化だけでなく、**保守費を残す**ことが重要です。
- 「保守」は健全度を回復し、「予防保守」は劣化やトラブルを未然に抑え、「サポート更新」は期限切れによる不利益を解消します。
- 教育を実施しても効果が定着するとは限りません。定着が弱い場合は再研修や報告しやすい職場づくりへの投資が有効です。
- リスクの予測値は意思決定の参考情報で、発生を保証するものではありません。

## v4.6 — 院内Wi-Fi認証情報の悪用イベント

- **学習設定：** 院内端末に保存されていた共有Wi-Fi認証情報が漏えいし、マルウェアに感染した医療者の私物PCから院内無線LANへの不審な接続が検知された、という架空のシナリオです。**Wi-Fiへの接続と、電子カルテ・医療機器等へのアクセスは同一ではありません。**
- **抽選：** EASYでは発生しません。5 WAVEモードはWAVE 4、7 WAVEモードはWAVE 6のみ抽選対象。3 WAVEでは発生しません。1プレイにつき最大1回。
- **目安確率：** 初期状態のNORMALで約15%、HARDで約30%。これは当該ウェーブの既存の運用事故の抽選枠を使った基準値です。報告体制・予防保守によって既存事故の確率がこの基準より低くなった場合、特殊イベントの発生確率も低下します。別の独立した運用事故を重複発生させません。
- **二段階構成：** WAVE内でWi-Fi接続異常が事前警告され、しばらくしてから侵入・拡大の判定が起こります。警告後に設備の追加・強化を行うこともできます。
- **防御の判定：** 中央の追加経路をカバーするネットワーク分離・EDR、職員教育の定着、報告体制の準備を点数化。十分なら追加の敵は0〜1体、不十分なら2〜3体（認証系／マルウェア系）が中央経路から出現。
- **影響：** 抑制件数には、対策によって回避できた分だけを計上します。防御が不十分な場合の抽選上の未出現は抑制として扱いません。事前に診療継続度を無条件で減らすことはありません。出現した敵を防御できなかった場合のみ通常の侵入被害が生じます。
- **振り返り：** 発生件数、追加脅威数、抑制した件数を結果画面とイベントログに表示します。

本イベントのシナリオ・確率・対策効果はすべてゲーム用の仮定です。現実のネットワーク設計・侵害状況・セキュリティ製品の効果について実証された数値を示すものではありません。

## v4.8 — Grok・ミーナ先生の統合デバッグ結果に基づく修正（優先 1・2・4・5）

今回は次の4系統に対応。③の再読み込み・保存対応はユーザー指定により未実装です。ブラウザ上のHTML/JavaScriptでも保存と復元は可能ですが、保存範囲・端末共有・破損時の対応設計が必要です。

**1. 終了時の更新待ち表示**
- 強化が遅延した際に「自動完了予定WAVE」をその場で確定・保存します。
- ミッション中は無料で待つ完了時期と有料追加検証費用を表示します。
- 敗北などのミッション終了後、未完了の強化は「ミッション終了：未完了／当初の予定」として表示します。実行できない次WAVEを新たな完了予定として案内しません。既払いSPと未完了Lvを確認できます。

**2. チュートリアルとダイアログの重なり**
- 「遊び方」「終了確認」などのモーダルを優先表示します。モーダルを開いている間はチュートリアルの説明パネル・スポットライトを隠し、閉じるとステップに復帰します。
- チュートリアルのガイドがモーダル本文を覆っていた重なりを解消します。

**4. 健全度と設備性能の整合性**
- 健全度・サポート・更新待ちによる「防御効率」の係数は攻撃力に1回だけ適用し、攻撃間隔には重複適用しません。これにより、射程や実際の狙いを除いた理論DPSも表示効率に比例します。
- 健全度低下により実効Lvが下がったとき、相性ボーナスとネットワーク分離の減速時間も**実効Lv**で計算します。
- この修正によって、劣化したタワーの実効DPSが旧版より高くなる場合があります。保守判断やゲームバランスは次の試行で比較してください。

**5. HARD専用の暫定バランス調整**
- **HARD初期SP 360→420**（+60）。初期にメールフィルター・MFA・EDRなどを組み合わせる余地を作ります。
- **HARD W1の敵構成**を、フィッシング8体・認証4体・マルウェア2体（合計14体）に変更。従来はフィッシング10体・認証4体でした。事前の脅威予測をゲームログ・遊び方に表示します。
- **HARD W6の敵HP×1.12、W7×1.15**。ベースのWAVE倍率に追加で乗算します。
- **HARD W5/6/7の撃退SP**を、通常の90%/80%/75%（端数は四捨五入）に調整。撃退スコアは変更しません。WAVE 5の7 WAVE用突破ボーナス+170 SPは維持します。
- EASY、NORMALのW1構成・初期SP・HP・撃退SPは変更しません。チュートリアルは従来の開始SP 360、固定W1構成で動作します。
- これらの数値は**未検証の調整仮説**です。実装上の動作チェックと、プレイによるゲームバランスの適切さは区別して判断してください。
